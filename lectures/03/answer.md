# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  - 質問「AIE2026の講座の宿題にある「3レベル」とは何ですか？」で比較した。
  - 第1回の `app.ask`（ツールなし）は、「具体的な講座のシラバスが手元にないため一般論になる」と前置きしたうえで、「初級・中級・上級」「理解から創造へ（ブルームのタキソノミー）」「プロンプトの習熟度」という3つのパターンを推測で挙げた。どれも実際の内容とは違い、最後は「講師やTAに質問する」ことを勧めて終わった。出力は700トークンと長かった。
  - エージェントは `search_glossary({'query': '3レベル'})` で用語集を検索し、用語「宿題の3レベル」の定義にもとづいて、「基礎（講義内容の確認）」「実装（自分でコードを書く）」「発展（調査や試行）」の3段階で、どれか1つに取り組めば完了、と正しく答えた。最後に「関連する回：第1回」も示した。
  - 素のLLMは講座固有の情報を持っていないため、もっともらしい推測しかできない。エージェントはツールで根拠となるデータを取りに行けるため、短く正確に答えられた。

- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 「3レベル」の質問：`search_glossary({'query': '3レベル'})` の1回。
  - 「LoRAとQLoRAの違いは？」：`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の2回。docstring の「query には調べたい用語を1つだけ入れる」に従い、用語を分けて検索していた。
  - 「第2回の内容から確認問題を1問出して」：`make_quiz({'lecture': 2})` の1回。「第2回」という文章から、引数を整数の 2 に変換して呼んでいた。INSTRUCTIONS には「必ず search_glossary で確認する」とあるが、4回実行していずれも search_glossary は呼ばなかった。指示は必ず守られるルールではなく、モデルが状況に応じて判断していると考えられる。

- 1つの質問での LLM 呼び出し回数（`requests`）：
  - 第1回の `app.ask`：ツールなしで1回だけ（入力21トークン、出力700トークン）。
  - 「3レベル」の質問：requests=2、tool_calls=1（入力923トークン、出力159トークン）。
  - LoRA/QLoRA の質問：requests=2、tool_calls=2。2回の検索を1回目の呼び出しで同時に指示し、2回目で回答を作っていた（順番に検索していれば3回になるはず）。
  - 確認問題：requests=2、tool_calls=1（4回とも同じ）。
  - エージェントは、指示（INSTRUCTIONS）とツールの説明を毎回モデルに送るため、入力トークンは素のLLMより大幅に増える（21 → 923）。一方で、根拠のある答えを短く返すため、出力トークンは減った（700 → 159）。

- 追加したツールと、docstring に書いた説明：
  - `make_quiz(lecture: int) -> str`：指定した回の用語から1つを `random.choice` で選び、`{"question": "「用語」の意味は？", "answer": 定義}` を JSON で返す。該当する用語がない回（例：第99回）では、エラーにせずメッセージを返す。テストも追加し、`uv run pytest -q` で14件すべて成功した。
  - docstring：「指定した回の用語から、意味を答える小テストを作る。学んだ用語の理解度を確認したいときや、復習問題を出すときに使う。」
  - `--list-tools` で確認すると、モデルに見えるのは名前・docstring・引数の型（`{"lecture": {"type": "integer"}}`）だけで、関数の中身は見えない。モデルはこの説明だけを手がかりにツールを選んでいる。
  - 4回実行したところ、エポック、過学習、教師ありファインチューニング（SFT）、Hugging Face Hub と毎回違う用語が出題された。ランダムな選択や正確なデータの取り出しをコードに任せることで、用語集にもとづいた問題を毎回変えて出せる。
  - ツールは答えも返しているが、モデルは4回とも答えを伏せて問題だけを出した（docstring には指示していない）。
  - ツールの問題文は「「○○」の意味は？」で固定だが、モデルは「その意味や目的を説明して」「どのように性能を測るとよいか」など、答えの内容も使って問題を書き換えることがあった。最終的な出題文はモデル次第で、ツールの返り値どおりになるとは限らない。
  - 「ヒントを出すこともできます」と言った回があったが、このコマンドは1回の質問で終わるため、実際にはヒントも採点もできない。モデルは自分がどう動かされているかを知らない。
  - 「関係する回を示す」という INSTRUCTIONS の指示は毎回守られたが、「関係する回：第2回」「（関連する回：第2回）」「（第2回）」と書式は毎回ばらついた。
